# 记录链数据模型：当前态指针 + 急切渲染缓存

复刻像素蛋糕的非破坏编辑核心：每张图持有一条追加式**记录链**（每条记录 = 能力 + 参数 + 前驱指针），**当前态指针**指向生效记录，回滚 = 移动指针而非删除记录。与原版的惰性渲染（预览/全分辨率分离）不同，我们在记录追加时**立即渲染**，产物按（**当前记录输出哈希**, 能力, **规范化**参数, **mask 哈希**〔可空〕）内容寻址入缓存；原图永远只读。键含当前态哈希故**链位置敏感**：同参重调仅在回滚回同一链态后命中（零成本重试），不回滚的连续同参调用因输入已变必然重渲染——这是设计使然（每次生效编辑都基于其真实前驱）。外部素材（如 .cube LUT）按**素材规则**入键：内容 sha256 进 params（路径不进键），素材以 `material:<sha>` 固化（模式 docstring 纪律 7 为执行细则）。

## Considered Options

- **惰性渲染引擎**（原版做法）：拒绝。它服务于实时滑杆 GUI 与百兆 RAW，我们没有这类交互面，复杂度换不来收益。
- **破坏性编辑 + undo 栈**：拒绝。会失去"按调用标识回滚"的 agent 能力与操作可审计性——而这正是复刻此模型的全部理由（原版敢开放 MCP 也是靠它）。

## Consequences

- 每次生效编辑占用一份输出 JPEG **或 PNG**（RGBA 链态用 PNG 无损）的磁盘（缓存命中则零成本）；当前磁盘余量 **91.7GB**（doctor 实测 2026-10-21；原 56GB 为陈旧数字），自用规模足够，需在 README 标注缓存清理策略。
- 工具层接近纯函数：追加记录 → 查缓存/渲染 → 返回输出哈希；引擎无渲染时机状态，崩溃恢复只需重放指针。
- **渲染确定性是内容寻址审计的前提**（lead 裁入 2026-10-21）：推理后端锁定单一执行环境——onnxruntime 一律 CPUExecutionProvider（禁 CoreML 等异构 EP）；torch 设备首次加载定死并常驻。实证：LaMa MPS 绕缓存三连真实渲染字节一致、CPU 对照一致（同进程同设备确定性成立；跨设备位同是舍入吸收的 fixture 级观察，不作保证）。
